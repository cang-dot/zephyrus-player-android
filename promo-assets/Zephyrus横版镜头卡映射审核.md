口播已经使用 MiMo `mimo-v2.5-tts-voiceclone` 生成，成品时长为 110.56 秒。下面的时间以音频中的实际停顿为准，不按文字数量平均分配。

## 整体节奏

这支视频不是从头到尾保持同一种兴奋度，而是反复拉高、刹停和恢复：

1. 先把观众带进音乐节舞美，形成第一个高点。
2. 在“等一下”处突然刹停，把舞台缩进手机，完成产品揭示。
3. 九种播放器样式进入全片最快的一段。
4. 歌词能力放慢，让逐字进度和多声部真正可读。
5. 搜索刚带来期待，就用“先别急着高兴”和资源不可用提示打断一次。
6. 本地曲库与状态栏歌词恢复实用感，最后平静交代适用人群和下载位置。

情绪曲线：好奇 -> 舞台高点 -> 急停转折 -> 样式高潮 -> 功能沉浸 -> 喜剧式刹停 -> 实用惊喜 -> 克制结束。

## 统一视觉规则

- 成片为 1920×1080、30 fps，主要信息放在横版中央安全区域。
- 软件 UI 全部重新渲染，少文字、无图片，不显示真实歌名、封面、账号、口令或完整歌词。
- 合成歌词统一使用原创短句，最多一至两行。
- 音乐节实拍仅出现在软件 UI 之外，使用无品牌、无可辨认艺人、授权清楚的横版素材；找不到合适素材时改用程序化舞台动画。
- 关键操作用光标、点击反馈和页面状态表达，不额外堆叠说明文字。
- 全片只保留两处明显整活：开场突然插音乐节实拍，以及“先别急着高兴”后的资源不可用提示。

- 00:16：“等一下”前使用唱片刹停，留出约 0.25 秒近似静音。
- 00:23-00:42：BGM 回来并进入最快节拍，九种样式切点跟随鼓点。
- 00:42-01:07：减少鼓组，保留轻微进度声和声部进入声，让歌词可读。
- 01:07-01:24：搜索操作声逐步加快；资源不可用提示使用一次短促系统错误音，不使用夸张梗音效。
- 01:24-01:40：恢复稳定节奏，本地扫描与状态栏出现分别有一次轻点击反馈。
- 01:40-01:50.56：音乐收束，人群声在最后 12 帧短暂回归后停止。

## 本轮审核项

请重点确认以下三点：

1. 开场是否采用“2-3 秒授权音乐节实拍 + 程序化舞台”的组合。
2. 九种样式是否作为全片最高速的一段，而歌词能力段主动放慢。
3. “资源不可用”作为第二处整活是否保留在一秒左右，不再增加额外网络热梗。

确认后进入最终分镜：读取已选镜头卡的完整参数与参考实现，把每个镜头拆成帧级动作、转场、字幕和素材任务，然后开始完整视频制作。
